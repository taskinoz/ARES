# TF1 / TFO compatibility evidence

14 November 2026. Phase 2 targets Titanfall Online (TFORevive.Core 135) and
Titanfall 1 (R1Delta 3.0.5). Full compatibility remains open; this checkpoint
covers selected v29 record layouts, authored brush/flat-patch collision and
rigid props. Northstar and Apex/R5 are outside this milestone.

## Changes and checks

- Eight additional v29 record schemas cover water, cubemaps, world lights,
  lightmap headers, probes, prop probe indices, the probe tree and references.
  Checks include finite fields, indices, tree ranges/cycles and SKY/RTL plane
  sizes. These schemas stay separate from v37's different lighting layouts.
- R1Delta now honors `drop_sequential` instead of silently running those drops
  together. Each body is reported under its original index and destroyed before
  the next spawn. A four-barrel native sequence passed.
- Both adapters log final angles and local model bounds. Speed and transformed
  bounds expectations fail when their required data is missing. Old reports
  containing only velocity can still be checked for speed.
- `physics_observations.py --phy FILE.phy` projects a rigid prop's actual
  collision vertices through its recorded pose. `--floor INDEX Z` checks
  support within one unit and linear speed at most 0.1. Multi-solid articulated
  models are rejected. This is sampled flat-plane support, not broad physics
  stability, stacking, friction or buoyancy acceptance.

Native tests used an original authored map with a brush top at z=0 and a flat
patch at z=128. Both runtimes passed the same two rays and four box hulls with
identical event strings. A four-barrel simultaneous run in each runtime passed
speed and coarse support checks; the actual barrel PHY also passes the saved
pose checks. A separate R1Delta sequential run passed.

An eight-crate TFO run intentionally retained two coarse box-bottom failures.
Both affected crates had rolled onto their sides. Their visual bounds extend
about 1.2 units below the patch plane, but their actual PHY bottoms sit

Do not widen the original bounds expectations or rewrite those raw reports.
The earlier uninstrumented crate result cannot be diagnosed retrospectively.

The expanded validator exposed a missing fallback RTL plane in MRVN-Radiant's
unbaked v29 output. The compiler was fixed upstream in the local MRVN-Radiant
checkout; a fresh map passes the validator and loads in both runtimes. ARES
contains the validator, not the compiler fix.

Static/tool evidence: 154 ARES format-tool tests, 65 adapter tests, registry
validation, and 33 compiled/retail v29 maps pass. The corpus includes Angel
City, Colony, Fracture, Lagoon, Relic and TFO lobby. MRVN-Radiant also passes
231 tool tests and 55 compiler regression cases.

Local native reports live under MRVN-Radiant's
`.local/respawn/phase2-rtl-fixed/`: `r1-barrels2`, `tfo-barrels2`,
`r1-sequential`, `tfo-crates8`, and their `physics-support.json` analyses.
The source map, shared checks and compiler/BSP fingerprints are generated by
`tools/respawn/prepare_tf1_baseline.py` in that checkout. Game assets and raw
account-bearing game logs are kept local.

## Remaining acceptance gates

| Area | Current evidence | Required for full support |
| --- | --- | --- |
| v29 records | Selected structural schemas; six reference maps | Remaining layouts and cross-references, including shadow/CSM and physics blobs |
| Collision | Sampled brushes and a flat patch in both runtimes | Curved/transformed/backface cases, masks, real titans/projectiles and triggers |
| Physics | Rigid-prop poses/support in controlled scenes | Repeated stress and retail controls for the historical fall-through issue; stacking and speeds |
| Water | Static heights/material ranges; earlier TFO buoyancy control | Paired buoyancy, water visibility cells, underwater rendering/fog |
| Lighting | Plane lengths, layouts, probes and tree checks | RTL semantics and paired world/character visual parity |
| Assets | Staged barrel dependencies load in R1Delta | Complete materials/models dependency packaging for standalone releases |
| Gameplay | Baseline spawns and intermission camera | Every supported mode, objectives, traversal and navigation |
| Release | Reproducible authored baseline | Authored and converted maps packaged for both runtimes, with human matches |

Passing the current probes does not close these gates. New failures should be
retained with the runtime version, shared checks, map/compiler fingerprints and
the raw events that identify the failure.
